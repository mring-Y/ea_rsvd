# 已发表稀疏 GPU 求解器严格对照实验

本实验在同一张 GPU 上比较本文的完整随机 SVD 输出与官方 PRIMME_SVDS CUDA 求解器。
双方使用相同 CSR 矩阵、矩阵方向、输出 rank 和计算精度，均返回完整的 U、Σ、V。
输入矩阵及 PRIMME 官方源码随独立 AutoDL 包提供，因此默认不需要下载矩阵或访问 GitHub。
此目录是新补充实验；历史诊断量计时不会被冒充为完整分解计时。

## 在 AutoDL 上运行

选择带 CUDA 开发工具的 Linux 镜像，建议 CUDA 12.6 或 12.8，包含 nvcc、gcc、g++、Python 3.10 以上。
首次运行会在包内安装缺少的 NumPy/SciPy；不会调用 sudo、apt、交互式 read 或 input。
缺少依赖时使用本机验证过的 NumPy 2.2.6 / SciPy 1.15.2；已有依赖的版本会记录到结果中。
CPU 数值库已随独立包提供。CUDA 库仍由镜像提供。

解压后进入 `published_gpu_compare` 目录。为下一次审稿补齐对照，推荐顺序运行主比较与质量扩展，共 800 个配置：

```bash
nohup bash run_autodl_review.sh > published_gpu_review.log 2>&1 < /dev/null &
```

它生成主比较和质量扩展两个结果压缩包。A800 与 RTX 4090D 两档均已完成并独立核查，
现有结果无需重跑；此入口用于复现或扩展到其他设备。
主实验完成但含失败配置时仍继续第二档；检查阶段提前失败则停止，保留诊断包。
脚本自动识别 GPU 架构（A800/A100 为 80，RTX 4090D 为 89），编译固定版本的 PRIMME，
先做正确性检查。主比较使用 5 个矩阵、rank 16/32、5 个随机种子，每配置 1 次预热和 5 次测量。
每个随机 SVD 状态使用 p∈{8,24}、q∈{0,1,2}；PRIMME eps∈{1e-4,1e-5,1e-6}、块大小∈{1,8}。
双方各有 6 个候选配置，主比较共 600 个配置，每配置独立超时默认 180 秒。
这是限定规模的公开求解器比较，不需要重新运行以前的工程实验全集。

单独运行主比较可使用 `PROFILE=paper bash run_autodl_all.sh`。需要额外检查 rank 64 时，
使用 `PROFILE=full bash run_autodl_all.sh`，共 900 个配置。
高 rank 的 PRIMME 收敛和逐次完整因子导出可能耗时较长；600 配置档不提供 rank 64 的性能证据。

若希望进一步区分重构质量与奇异向量质量，可另跑 `PROFILE=quality`。该档保留全部 5 个
矩阵、rank 16/32 和 2 个种子，rSVD 使用 p=24、q∈{2,4,6,8}，PRIMME 使用
eps∈{1e-2,1e-3,1e-5} 和块大小 1/8，共 200 个配置，每配置测量 3 次。
它同时测试更深的幂迭代和较宽松的外部求解器容差，汇总仍按共同的实测质量判定。
该档与主实验分别保存，不沿用主实验的速度比。

可以先运行烟雾检查：

```bash
PROFILE=smoke bash run_autodl_all.sh
```

正式实验不需要等待烟雾检查才能启动：默认脚本本身已有 24 项 GPU 正确性检查，
均须产生完整因子并通过独立验证。极小矩阵的官方自动重启参数可能为零，导致输入检查
返回 `-118`；适配器只在 `min(m,n) <= 2*block_size` 时设置正的 `minRestartSize`。
默认公共矩阵不触发此分支，仍使用官方重启默认值。官方算法源码保持不变。
新版入口将详细日志同步写入启动日志，并且默认每 20 秒打印一次心跳；查看进度的方法见下文。
脚本结束会在包目录生成 `published_gpu_results_时间戳.tar.gz`，将它交回来即可。
单个配置失败会被记录并继续；退出码 2 表示存在失败或缺失矩阵，不表示其余实验没有完成。
若被外部强制 kill，保留相应 `results/时间戳` 目录，其中逐项结果已持续保存。

需要第二种精度时可单独运行 `PRECISION=fp64 bash run_autodl_all.sh`。
需要更长单项上限时设置 `CASE_TIMEOUT=300`。不要将超时改写成 OOM。
用户额外命令行参数直接传给 campaign.py，例如 `--matrices west2021 ca-HepPh`。

镜像包含 Compute Sanitizer 时，可设置 `RUN_MEMCHECK=1`。脚本在正式计时前检查两个后端、
两种精度和两种矩形方向，共 8 个小问题。此诊断只检查本目录的新后端；它不替代历史
tree/overlap 程序的内存诊断。工具路径可通过 `COMPUTE_SANITIZER=/path/compute-sanitizer` 指定。
默认不强制要求服务器安装该工具，缺少工具不会被记为已完成诊断。

如果进程被外部强制结束，可以执行 `python rebuild_summary.py results/时间戳/campaign`
从已写入的记录重建汇总；恢复汇总不会把未跑完的实验改标为完成。

## 查看进度与运行资源

新版入口可以直接监看启动日志：

```bash
tail -n 40 -F published_gpu_review.log
```

日志依次显示依赖检查、构建、GPU 正确性检查、正式配置、分析和归档。
每个配置有开始与结束记录；心跳显示当前阶段、阶段耗时、已保存配置数、结果状态及最近配置。
单个求解进程默认最多运行 180 秒，其后的独立 CPU 因子验证另计。
首次编译官方 PRIMME 的 25 个源文件和 CUDA 适配器时，GPU 使用率为零是正常现象。
CPU 验证和汇总阶段也可能出现 GPU 使用率为零。

旧版任务已经在后台运行时，不需要终止或重新提交。可以立即查看已有详细日志：

```bash
tail -n 40 -F results/*/logs/*.log
```

也可以仅将 `watch_progress.py` 放入正在运行的包目录，再执行：

```bash
python3 watch_progress.py --watch
```

监看器只读取日志和结果，可用于旧版任务，不更改求解程序、参数或记录。
需要指定任务时使用 `--run results/任务目录名`，需要更短间隔时使用 `--interval 10`。
心跳表示监看器仍在运行；是否有计算进展还应结合已保存配置数、日志更新时间和工作进程判断。
可在另一终端用 `pgrep -af 'run_autodl|campaign.py|gpu_compare|nvcc|cc1'` 查看工作进程。
`nohup: ignoring input` 是后台启动的正常提示，不表示等待交互输入。

完整离线包约 26 MB，解压约 73.5 MB。主要体积来自随包提供的 CPU 数值库约 54.6 MB、
五个矩阵约 12.7 MB、固定 PRIMME 源码约 6.0 MB；这些是磁盘文件大小，不是 RAM 或显存需求。
包内不含旧工程实验的完整数据集、生成的可执行文件或实验结果。

本机 RTX 5070 Laptop 的最大输入短跑使用 lp_osa_30（4350×104374、604488 个非零元），
FP32、rank 32，分别执行 rSVD p=24/q=8 和 PRIMME eps=1e-5/block=8，各 1 次预热和 5 次测量。
两项均完成并通过验证。约 0.15 秒加显存查询耗时的采样间隔下，campaign 进程树 RSS 最高
662.7 MiB，`nvidia-smi` 报告的全卡已用显存最高 502 MiB，开始前为 0 MiB。
此采样包含独立 CPU 验证，可能遗漏短暂峰值；编译、依赖安装和其他 GPU 的资源需求另计。
这些资源采样不用于论文中的速度测量，也不是整个云端任务的保证上限。

从已完成的本机网格累计各配置的进程墙钟与独立验证时间，rank 16/32 的 600 配置约为
40.3 分钟，质量扩展的 200 配置约为 9.5 分钟。两档合计约 50 分钟，另加编译、检查、
逐项汇总及归档。完整 900 配置网格约 116.8 分钟，高 rank 的收敛成本明显增加。
已经完成的 A800 80GB PCIe 实测中，正式 600 配置 campaign 的起止墙钟为 640.9 秒（10.7 分钟），
200 配置质量扩展为 163.7 秒（2.7 分钟）；合计 13.4 分钟，包含各配置验证和汇总，
首次编译、正确性检查和最终归档另计。RTX 4090D 的对应 campaign 实测为 682.0 秒
（11.4 分钟）与 179.1 秒（3.0 分钟），合计 14.4 分钟。两台云设备的这两档均无超时。
这些是指定输入、参数和环境下的实测耗时；其他设备或新增高 rank 仍可能耗时更久。
无需为这次对照重跑全部历史工程实验。

## 比较与验证范围

主要耗时是 GPU 上 CSR 就绪后，到完整 U、Σ、V 计算完成的同步墙钟时间。
包含每次求解的分配、随机矩阵生成、CPU 控制、最终向量形成；本文路径还包含完整残差诊断、
投影谱监测和 Q 正交性检查。矩阵读取、驻留初始化、因子导出、FP64 验证另列。
因此此处不是 CUDA 事件的局部阶段计时。两者使用同一 cuSPARSE CSR 乘法适配层。

每次计时重复的完整因子都独立验证，质量匹配采用重复中最差的实测误差，时间采用中位数。
能量残差核对针对最终一次完整因子，另保存该次重构误差，避免与最差重复的质量混用。
PRIMME 的每次 matvec 数和 locking 警告分别记录，任一计时重复出现 locking 警告的配置
不进入有效对照；预热警告另列。
FP32 的验证矩阵是先舍入为 FP32、再提升到 FP64 的实际输入值。一般低秩误差包含 Gram 和
交叉项，不假设奇异向量完全正交；接近零残差时切换到分块直接重构。另检查左右向量正交性
和奇异三元组残差。正交误差大于 1e-3 的配置不进入有效对照。

PRIMME eps 是奇异三元组收敛容差，不能与 Frobenius 重构阈值直接等同。
`quality_comparisons.csv` 比较同输入、同 rank、同精度、同种子的实际误差目标。
`near_reference_comparisons.csv` 进一步使用经过验证的较严格 PRIMME 配置为数值参照，
限制为参照重构误差的 1.01 或 1.05 倍；参照不被称为理论最优解。
所有配置、警告、失败、未达到目标的情形保留在 records.jsonl 和 records.csv 中。
有限网格最小耗时属于离线校准，候选探索的实际开销也单独记录；不能声称这是免费在线调参。
`analysis.md` 按矩阵和 rank 列出有效配置数、严格质量配对数与速度比；
`calibration_costs.csv` 汇总所有候选的进程墙钟时间（包括失败和超时）及独立验证时间。
主比较匹配低秩重构误差；`joint_quality_comparisons.csv` 还同时要求共同的奇异三元组残差
上限，以区分近似重构与更高精度的奇异向量求解。两者都会报告不能达到目标的情形。
若某个联合质量目标未达到，可用 `--powers 0 1 2 4 6 8` 扩大幂迭代网格，
或通过 `--oversampling` 扩大子空间宽度。网格内未达到目标属于结果边界，不能自动解释为硬件无法运行。
`cpu_crosscheck.py` 可在 GPU 计时结束后用 SciPy/PROPACK 再核查公开矩阵的谱与重构误差：

```bash
python cpu_crosscheck.py --campaigns results/时间戳/campaign --out results/独立CPU核查
```

该步骤以 FP64 求解实际输入值，记录每个矩阵/精度的超时或收敛失败；它是独立数值参照，
不进入 GPU 速度比较，也不被称为最优性证明。
外部对照中的 rSVD 是用共同的供应商 CSR 后端返回完整因子的诊断参考路径，
不复用旧 CUDA-event 时间，也不代表旧 reduction-tree/overlap 实现的性能。

## 本机与云端证据

本机 GPU 为 RTX 5070 Laptop 8GB。A800 80GB PCIe 的主比较和质量扩展已独立运行并核查，
共 800 配置，实际 CUDA 工具链及运行时为 11.8。主比较 598/600 配置有效；质量扩展
135/200 有效，包括全部 80 个 rSVD 配置，PRIMME 有 63 个正交性未达标和 2 个求解失败。
主比较另有 2 个 PRIMME 求解失败；两档共四个求解失败均保留实际错误码及未齐的收敛 rank，未记为 OOM。
近参考重构配对为 50/50 与 20/20，PRIMME/rSVD 时间几何均值为 7.16 与 3.35。
扩展档中 18 组 rSVD 更快、2 组 PRIMME 更快；加上三元组残差 ≤1e−3 / ≤1e−4 时，
配对为 16/20 / 12/20，时间比为 2.26 / 2.99。未达标组仍保留在总组数内。
同一 200 配置扩展网格的核心源码、有效输入值哈希及参数与本机一致；本机重构时间比为 3.33。
本机主网格另含 rank 64，共 900 配置，不能把它与 A800 的 600 配置比值直接当作硬件迁移效应。
RTX 4090D 24GB 的同协议主比较和扩展已完成：592/600 与 138/200 配置有效，全部
380 个 rSVD 配置通过；PRIMME 共 6 个求解失败和 64 个正交性未达标，无超时。
失败保留实际非零错误码和未齐 rank，未归因于 OOM。两档近参考重构配对为 50/50
与 20/20，时间比分别为 7.66 与 3.51，rSVD 在这些配对中均更快。扩展档增加
三元组残差 ≤1e−3 / ≤1e−4 时，配对为 16/20 / 12/20，时间比为 2.37 / 2.75。
A800 与 RTX 4090D 的 600 配置主网格、200 配置扩展网格的输入、参数、数值求解
和分析源码相同。RTX 运行器只增加了一行运行前进度提示，保留其不同源码哈希；
数值与计时协议一致。三设备扩展网格均形成 20/20 近参考重构配对，且在严格三元组
要求下保留相同的 16/20 与 12/20 覆盖率。各时间比在设备内部计算，不代表硬件间
的直接速度比。旧诊断 CUDA-event 数据保持原有用途。
PRIMME 是已发表求解器的官方 GPU 软件版本，不是官方 GPU 随机 SVD 论文实现。
Tomás 等近邻工作的作者程序尚未取得，若需要其原版对照，仍需取得并核实作者源码。

## 源码与构建

`build_gpu.py` 按官方 src/Makefile 的编译单元和 CUDA 标志调用编译器；官方算法源码不作修改。
只需要 Python 和现有编译器，不依赖 make。自动校验官方源码及数据的 SHA256。
生成记录包含 PRIMME commit、CUDA/GPU/驱动信息、输入哈希和代码哈希。
结果包还保存本次运行的核心源码副本与可执行文件哈希；开始实验前核对构建清单，
若源码或二进制与清单不一致则要求重新编译，以保持代码与测量对应。
源码版本可不带二进制数值库，使用 `BLAS_LIB_DIR` 和 `BLAS_LIBRARIES=lapack,blas` 指定已装库。
从 GitHub 克隆源码时，先在本目录运行 `python fetch_assets.py` 获取固定 PRIMME 归档和官方
矩阵；该步骤记录下载日志、支持断点续传，并跳过失败矩阵。独立 AutoDL 包已包含这些资源，
无需运行此下载步骤。
第三方归属见 THIRD_PARTY.md。
